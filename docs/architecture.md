# Architecture notes

This doc collects the deeper rationale behind the node choices and the
16 GB VRAM budget. Skip if you just want to run the build.

## Why Canny (and not Pose or Depth)

The official ComfyUI template ships a **Pose** preprocessor
(`SDPose Video Pose Extractor [Multi-Person]`) but the SDPose custom node
isn't bundled with a default ComfyUI install. Depth Anything 3 is in core
but its model weights aren't pre-downloaded in the example workflow.

Canny is built into `comfy_extras/nodes_canny.py` and uses **kornia** under
the hood. No extra weights. The model produces reliable edges from any
source frame and gives the controlnet a stable structural cue without losing
the camera/scene context the way Pose would for a single-person subject.

For higher-fidelity control on a beefier GPU, swap the Canny node for the
Depth Anything 3 tutorial preprocessor or install SDPose and wire its pose
frames in.

## Why downscale Canny to 432×240

Canny at the source's native 864×480 with 124 frames allocates ~3.8 GB on
top of an already-loaded H3 stack (UNet + Qwen3 + controlnet + VAEs). On a
16 GB card that pushes the device limit (15.47 GB PyTorch view with
`--reserve-vram 0.5 --vram-headroom 1`) and PyTorch's caching allocator
fails to find a contiguous 3.8 GB block — even though total fragmentation
budget is technically available.

432×240 cuts the Canny working set to ~600 MB which fits cleanly. The
`MiniMaxH3FunControlPatch._fit_frames` method resizes the control video
to the target output dimensions (`width × height`) on every step, so the
controlnet still produces edges at the resolution H3 generates at.

If you have ≥24 GB VRAM, delete the `ImageScale` node (id `850`) and let
Canny see the source at full resolution.

## Why `MiniMaxH3AudioDrive` (and not the default audio latent)

H3's native audio generation produces plausible sound for the prompt
description, but **it does not preserve the source clip's audio**. For
motion transfer we want the original soundtrack untouched.

`VRGDG_MiniMaxH3AudioDrive` from the `comfyui-vrgamedevgirl` custom
node pack does three things:

1. Encode the source audio through the H3 audio VAE into H3's AV latent
   audio slot.
2. Replace the AV latent's audio half with the encoded source. The video
   half is left empty (still to be generated by sampling).
3. Mark the audio half with a **zero denoise mask** so the sampler
   doesn't touch it during the diffusion steps. Only the video half is
   denoised.

After sampling and decode, the audio passes through unchanged into the
muxed output via `CreateVideo` (which combines images + audio into the
final `VIDEO` object that `SaveVideo` writes).

The official ComfyUI template uses the same approach via the
`MiniMaxH3AudioDrive` path implicitly through the audio conditioning
slots; VRGDG's wrapper is just the explicit version of that.

## Why `--lowvram` and **not** `--disable-smart-memory`

`--disable-smart-memory` keeps models resident in VRAM between phases,
which is what triggered the first OOMs. With smart memory on (the
default), ComfyUI offloads models to system RAM when their owning phase
ends and reloads them when the next phase needs them. The `--lowvram`
flag keeps UNet/CLIP in smaller on-device buffers via
`comfy.model_management.load_models_gpu()` chunking.

On this 16 GB card the working combination is:

```bash
--fp8_e4m3fn-unet        # H3 unet to FP8 (saves ~3 GB vs default fp16)
--fp16-vae               # VAEs at FP16 (int8 VAE file is preferred where available)
--lowvram                # chunked model loading
--reserve-vram 0.5       # leave 0.5 GB for system/CUDA context
--vram-headroom 1        # +1 GB reserve on top of reserve-vram
```

`--vram-headroom 1` is the critical knob for fitting H3 + ControlNet in
16 GB; the H3 skill notes the proven default is `--vram-headroom 2` for
the ref2va + reference-image workflow alone, but with the ControlNet
patch loaded you need the extra GB back.

## How to extend to multiple reference images

The `MiniMaxH3ReferenceToVideo` node accepts up to **9** reference images
(`ref_image_0` … `ref_image_8`) plus 3 reference videos and 3 reference
audios. To add more, drop additional `LoadImage` nodes in the graph, then
patch the corresponding `ref_images_#N` input in the API-format JSON.

For a "cast swap" demo: use `ref_image_0` for the new character and
`ref_image_1` for the new location/wardrobe. The controlnet still drives
the motion from the source video.

## How to swap preprocessors

Canny is a placeholder. Replace node `800` (Canny) with one of:

- **Depth Anything 3** (`comfy_extras/nodes_depth.py`) — captures scene
  geometry, often more useful than Canny for outdoor clips
- **SDPose** (`https://github.com/comfyanonymous/ComfyUI_experiments` or
  community packs) — skeletal pose, ideal for character motion
- **MLSD** (line segments) — good for architectural scenes
- **HED** (holistically nested edge detection) — soft edges, good for
  organic shapes

All of these feed into `MiniMaxH3FunControlNetApply.control_video`
unchanged. The H3 Fun ControlNet-Union was trained on all five and any
of them work as a drop-in replacement.
